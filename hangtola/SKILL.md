# Hangtola 夯到拉排行榜生成器

把一组条目（产品、游戏、人物、工具……）按自定义维度调研、打分，产出五档榜单：
**夯**（超神）→ **顶级** → **人上人** → **NPC**（平庸）→ **拉完了**（垃圾）。

交付物是独立运行的单文件 HTML 编辑器（模板 `assets/template.html`）：经典黑框浅色
tier list 网格（导出即所见），外壳为 Apple 设计系统 + 底部悬浮 touch bar，
支持深浅色切换，导出图干净无水印。

## 工作流

### 1. 记忆检查（.hangtola/）

在当前工作目录查找 `.hangtola/`：

```
.hangtola/
├── dimensions.json      # 维度记忆：{ "<主题>": { "dimensions": [...], "updatedAt": "..." } }
└── boards/<slug>.json   # 历史榜单数据（与 HTML 内嵌数据同 schema）
```

- 存在且主题匹配 → 告知用户找到历史维度/榜单，询问是复用、修改还是重来。
- 用户要求"继续编辑上次的榜"→ 直接读取对应 `boards/<slug>.json` 注入模板。
- 用户在 HTML 里编辑过并导出了 JSON → 让用户提供该文件（或其路径），以它为最新真相。

### 2. 收集条目

- 用户已给出条目 → 直接使用。
- 用户只给主题（如"2026 年旗舰手机"）→ 用可用的网络搜索工具（WebSearch / agent-reach）
  搜出候选条目清单，列出让用户确认增删（通常 8~20 个为宜）。

### 3. 确认排序维度

维度即"自定义提问"，决定榜单的灵魂。流程：

1. 若记忆中有同主题维度，优先展示复用。
2. 否则根据主题提出 3~5 个建议维度（各带权重 1~5），用 AskUserQuestion 或直接列出
   让用户确认/修改/追加。示例（手机主题）：性能(3)、影像(2)、续航(2)、价格诚意(3)。
3. 用户可随时说"按 XX 排"覆盖全部维度。

### 4. 调研

对每个条目按维度主动搜索客观信息（评测、参数、口碑、销量、社区风评）。
条目多时可并行派 Explore/general-purpose 子代理分组调研。每个条目的定档理由写进
`note` 字段——**页面不显示它**（导出图必须干净），它只作为数据记忆随 JSON 留存，
供下次续榜时回忆定档依据；给用户看的理由在对话里呈现。

### 5. 打分定档

- 每维度 0~10 分 × 权重 → 加权总分，按总分排序后定档。
- 定档纪律：**夯是稀缺的**（≤ 20%，无愧于"超神"才给）；拉完了必须有硬伤依据；
  中庸无亮点的进 NPC；不强行凑满每档，某档可以为空。
- 在对话中先给出榜单文字版 + 每条目一句话理由，让用户过目（若用户催促可直接出图）。

### 6. 生成 HTML

1. 复制 `assets/template.html` 到工作目录，命名 `夯到拉-<主题>.html`。
2. 构造数据 JSON（schema 见下），替换文件中
   `<script id="hangtola-data" type="application/json">{}</script>` 的 `{}`。
   **注意**：JSON 字符串内若含 `</script`，须写成 `<\/script` 防止提前闭合标签。
3. 图片：模板须离线运行，`image` 字段禁止外链 URL。若调研拿到条目配图，下载后压缩
   （保留原始比例，长边 ≤512px、JPEG）转 base64 dataURL 填入；否则留 `null`（纯文字
   卡片，反色墨块样式本身很醒目），用户可在 HTML 里自行上传或粘贴图片。
4. `footnote` 为底部声明条（黑底白字，咬在网格底边）。**默认已有免责声明，不必注入**——
   省略该字段即用模板默认值；只有用户要求换措辞时才写自定义文案，明确写 `""` 才是不要这条。

### 7. 写入记忆

- 合并维度到 `.hangtola/dimensions.json`（按主题为键，带 `updatedAt`）。
- 榜单数据存 `.hangtola/boards/<slug>.json`（slug 用主题拼音或英文短名 + 日期）。
- 目录不存在则创建。

### 8. 交付

在浏览器中打开生成的 HTML，并告知用户：

- 拖动卡片定档；轻点 / 长按 / 电脑右键卡片 → 同一张操作单（定档色块、改名、删除）。
- 标题、档位名、底部声明条都在页面上直接点开就能改；声明条清空即消失，
  「⋯ → 底部声明」可改写或一键恢复默认。
- ☾/☀ 切换深浅色，导出图配色跟随当前模式。
- 「导出图片」选 3:4 / 4:3 / 16:9 即出干净 PNG（无水印；标题留空则纯网格）。
- 「⋯ → 导出数据」的 JSON 交回给 AI（或存入 `.hangtola/`）即可续榜。

## 数据 Schema

```json
{
  "id": "phones-2026",
  "title": "2026 旗舰手机 夯到拉",
  "savedAt": "2026-08-03T12:00:00.000Z",
  "dimensions": [{ "name": "性能", "weight": 3 }],
  "tiers": [
    { "key": "hang",  "label": "夯",     "color": "#fb2018", "items": [
      { "text": "iPhone 17 Pro", "image": null, "note": "性能影像双榜第一，无短板", "color": null }
    ]},
    { "key": "top",   "label": "顶级",   "color": "#ffa640", "items": [] },
    { "key": "upper", "label": "人上人", "color": "#fbf600", "items": [] },
    { "key": "npc",   "label": "NPC",    "color": "#fdf1c7", "items": [] },
    { "key": "la",    "label": "拉完了", "color": "#ffffff", "items": [] }
  ],
  "pool": []
}
```

- `id`：榜单唯一标识，模板用它隔离 localStorage 自动保存；同一榜单迭代时保持不变，
  且每次注入须刷新 `savedAt`（模板以时间新者为准，保护用户的本地编辑）。
- `note`：AI 的定档理由，仅存于数据、不显示在页面，续榜时用。
- `title`：可选。很多榜单不需要标题——用户没明确要就注入 `""`（导出纯网格）；
  要标题时才填主题名。页面留有占位提示，用户随时可点出来补写。
- `footnote`：底部声明条。字段缺失 = 用模板默认免责声明；`""` = 用户主动清掉，不显示、不占位。
- 条目 `color`：仅文字卡生效的底色（iOS 系统色：#ffffff / #ff453a / #ff9f0a /
  #ffd60a / #30d158 / #0a84ff / #bf5af2），`null` = 默认墨块。AI 一般留 `null`，
  除非用户要求按颜色语义分类（如阵营、品牌色）。
- `pool`：备选区（未定档条目，不进导出图）。
- 五档 `key / color` 固定；`label` 是默认值，用户可在页面改（序列化会保留用户改名）。
