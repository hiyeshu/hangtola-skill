## 输入归一化

使用一条内部记录贯穿识别、调研、定档和生成：

```text
sourceIndex → text → image → caption → note → color → tier → position
```

- `sourceIndex` 只用于保护附件与文字配对，不写入最终 schema。
- 同一消息里有 N 张图片和 N 段编号说明时，按编号配对；没有编号时按出现顺序配对。
- 一段文字明显描述相邻图片时优先绑定到该图片；不能确定时保留为独立纯文字项，不擅自吞并。
- 文件名只在像真实名称时采用。`IMG_1234`、`Screenshot`、时间戳等不能当条目名。
- 重复图片或重复文字先保留并标记，只有确认是同一条目时才合并。

## 三类文案

### `text`：名称

写稳定身份，不写评价。例：`iPhone 17 Pro`、`杨枝甘露`、`方案 B`。

### `caption`：公开短评

写一个能独立读懂的观察或判断，默认不超过 14 个汉字或 36 个拉丁字符：

- 好：`续航像开了外挂`、`贵，但每一刀都值`、`气氛组唯一真神`
- 差：`非常好用`、`这个很不错`、`综合表现优秀，值得推荐`

保持简单、清晰、有趣。幽默来自准确，不来自堆梗；不要虚构事实，不做人身攻击，不重复条目名或档位名。用户已有备注时优先保留其语气，只做必要压缩。

### `note`：内部依据

记录评分证据、取舍和不确定性，可比 `caption` 更具体。它随 JSON 保存，但不出现在卡片或 PNG 中。

## 纯文字智能配色

只从以下值选择，保证模板能自动计算黑白前景色：

| 颜色 | 建议语义 |
| --- | --- |
| `null` | 无稳定语义、保持中性 |
| `#ffffff` | 极简、基础、留白 |
| `#ff453a` | 激烈、警告、争议 |
| `#ff9f0a` | 活力、食欲、热闹 |
| `#ffd60a` | 明亮、幽默、注意力 |
| `#30d158` | 自然、健康、通过 |
| `#0a84ff` | 科技、理性、可靠 |
| `#bf5af2` | 创意、神秘、风格化 |

按条目自身语义选色，不按所在档位机械映射。不要为了“丰富”给每张文字卡不同颜色；同一语义应保持一致。图片卡一律使用 `null`，避免颜色参数成为死数据。

## 典型输入

### 多图，无说明

逐图识别，生成稳定名称和公开短评。只把识别不确定且会改变定档的图片集中列出询问。

### 多图，加一段总备注

把总备注作为排序意图或维度来源，不要复制到每张卡。每张卡仍生成自己的 `caption` 和 `note`。

### 图片逐项配文

保留用户配文的核心意思：名称写入 `text`，适合公开展示的判断压缩进 `caption`，较长依据写入 `note`。

### 纯文字

直接建立条目，不要求补图。AI 可根据语义填写 `color`，但没有稳定语义时保持 `null`。

### 图片与纯文字混合

使用同一评分与定档规则。不要因为有图片就给予更高权重，也不要为纯文字项虚构图片。
